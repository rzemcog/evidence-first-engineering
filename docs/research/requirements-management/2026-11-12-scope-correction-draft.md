# Draft: корректировка цели и методов исследования

**Статус: DRAFT, требует отдельного утверждения пользователя.** Дата: 2026-11-12.  
**Основание:** замечания пользователя после обсуждения [плана сценариев](experiments-plan.md).  
**Суть:** предыдущий план испытаний сместил исследование существующих инженерных решений в сторону эмпирического исследования недетерминированного поведения LLM-агентов.

## Зафиксированная постановка проблемы

1. **Функциональность преимущественно выясняется изучением исходного кода, документации, опубликованных тестов и архитектуры.** Не требуется воспроизводить каждую возможность практическим запуском.
2. **Надёжность поведения конкретного агента** зависит от модели, harness, окружения, прав и промптов. Массовая экспериментальная проверка этого поведения — отдельный самостоятельный проект, не входящий в текущие цели.
3. **Не ищем единую систему, полностью соответствующую D-001–D-013.** Исследуем существующие методы, механизмы, идеи, ограничения и возможные сочетания, затем формируем универсальный набор вариантов и нашу композицию.
4. Работа **двунаправленная (D-013)**: требования выявляют направления поиска; открытые решения обнаруживают пропущенные возможности и вызывают новые draft предложений.
5. Создание собственного фреймворка не считается предварительно выбранной целью.

## Предлагаемая коррекция исследовательской методики

**Основной метод:** качественный технический разбор: первоисточники → код и конфигурация → модель данных/контроля/доверия → сильные и слабые стороны → сравнение с альтернативами → идеи переиспользования и комбинирования → предложения для нашего профиля/новых требований.

**Типы выводов:** подтверждено исходным кодом; заявлено документацией; заявлено автором; выведено из анализа; не проверено/неизвестно. Отдельно сохранять версии продукта и ссылки на материал.

**Точечные испытания:** допускаются как вспомогательный инструмент только если существенное для выбора механизма поведение не удалось определить по публичным источникам, либо нужно проверить техническую совместимость компонентов. Для каждого такого испытания зафиксировать нерешённый вопрос и почему документации/кода недостаточно. Не утверждать обязательность испытаний по всем кандидатам.

**За пределами текущего ресерча:** массовые многократные прогоны agent workflows для измерения надёжности модели/harness; статистический анализ недетерминированности; соревнование по отказоустойчивости агентов; поиск «победителя», единолично покрывающего требования. Эти направления могут упоминаться как ограничения и смежные исследования, но не становятся задачами проекта без отдельного решения.

## Что делать с предыдущими артефактами

- [Первую сравнительную матрицу](2026-11-12-comparison.md) сохраняем как **исторический первый срез**, не как итоговую систему оценки. В будущих сравнениях приоритет у идей и структурного анализа, а не полноты чек-листа.
- [План T01–T07](experiments-plan.md) сохраняем для прозрачности. **Предлагается снять его статус ближайшего обязательного исследовательского этапа**: он может служить справочником сценариев или основой для будущего проекта по harness/model reliability.
- [Аудит GRACE 4](2026-11-12-grace-requirements.md) дополняем изучением исходников и механизмов; не требуем статистических тестов с агентами как условия для использования выводов.
- По результатам исследований раздельно поддерживаем [универсальные варианты](../../universal-options.md) и [нашу композицию](../../our-composition.md).
